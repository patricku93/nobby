# NoBby v2.1 — widget sizing, transparency, ring style, setup status

Date: 2026-11-03
Status: owner decisions taken 2026-11-03 (answers below)
Builds on: `2026-11-03-nobby-v2-sticker-diary-reskin-design.md` (released as v2.0.0)

## 1. Widget can be resized to any width

The widget currently cannot be stretched wider than 3 grid cells. The
`appwidget-provider` metadata must allow horizontal and vertical resizing up
to the full launcher width (`resizeMode="horizontal|vertical"`, generous
`maxResizeWidth`/`maxResizeHeight`, `targetCellWidth`/`targetCellHeight` on
API 31+, sensible `minResizeWidth`). The existing responsive layouts (2×1,
2×2, 4×2 classes) are picked by size; wide sizes use the 4×2 layout.

## 2. Background transparency (owner: background only)

- Widget settings get a "Hintergrund" / "Background" slider: opacity
  0–100 % in 10 % steps, default 100 % (opaque, as today).
- It affects only the widget background. Text, ring, mascot and the Done
  button stay fully opaque. Below ~40 % opacity text readability depends on
  the wallpaper; the settings screen shows a live preview on a sample
  wallpaper strip so the user can judge. (Glance has no text shadow.)
- Stored in the widget config (DataStore) and applied in light and dark for
  every preset.

## 3. Widget style: Ring or Classic (owner: style choice)

- Widget settings get a style choice: **Ring** or **Classic** (current
  layout, default stays Classic for existing users; new installs default to
  Ring).
- **Ring:** the bead bracelet from Home with the countdown number and label
  in the centre, in the active preset colours and ring tone (wear, pause,
  due, overdue, safety). Square sizes show the ring only (with the NoBby
  sticker from 2×2 up); wide sizes show the ring left and the next event +
  Done (when due) right. Because Glance cannot draw on a Canvas, the ring is
  rendered to a bitmap with the same painter Home uses and shown as an
  Image; it is re-rendered on every widget update (state, preset, mode,
  size). Bitmap failures fall back to the Classic layout.
- Tap opens Home; Done appears only when an event is due or overdue, as
  today.

## 4. Setup asks where the user stands first (owner: In / Out / Not started)

Onboarding gains a first question before the cycle lengths:

| Answer | Next question | Resulting state |
|---|---|---|
| Ring is in | When did it go in? (date + time) | Anchor = that insertion; wear phase. |
| Ring is out (pause) | When did it come out? (date + time) | Anchor = removal − wear days; the removal is logged as confirmed, so Home shows the pause counting down to the next insertion and no overdue appears. The removal may not be more than the configured pause ago; if it is, the app says the pause is over and asks for the planned insertion instead. |
| Not started yet | When will the first ring go in? (date + time, today or later) | Anchor = that future insertion; Home shows "Ring rein in N Tagen" with the INSERT reminders, nothing overdue before it. |

The rest of onboarding (lengths, reminders, theme) is unchanged. Safety
warnings and the 7-day pause bound apply exactly as for confirmations.
